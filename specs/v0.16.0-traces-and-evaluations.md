# v0.16.0 — Structured Traces and Evaluation Harness

## Status

Draft

## Learning Question

What can be measured and regression-tested when every application-owned decision, model boundary,
tool boundary, context replacement, evidence link, recovery action, and terminal result produces a
versioned structured event?

## Problem and Rationale

Releases 0.11–0.15 add durable evidence, claims, recovery, and context policy. Terminal progress and
artifacts expose individual runs but cannot reliably compare versions or prove that later
parallelism improves quality. Release 0.16.0 introduces a trace and evaluation substrate before
concurrency amplifies cost and coordination complexity.

OpenTelemetry defines traces as the path of a request through an application and distinguishes
traces, metrics, and logs as correlated observability signals; see the official
[signals documentation](https://opentelemetry.io/docs/concepts/signals/) and
[context-propagation guidance](https://opentelemetry.io/docs/concepts/context-propagation/).
OpenAI's Evals API supports versioned data schemas, testing criteria, graders, model runs, and
per-model token usage; see the official
[Evals API reference](https://platform.openai.com/docs/api-reference/evals/deleteRun). This release
implements a local, provider-visible learning harness and may export compatible data later.

## Primary Mechanism

Emit immutable `RunEvent` records with causal parent IDs and artifact references, then execute a
versioned JSONL evaluation corpus with deterministic graders and optional model graders. Traces
record observable application state, never private chain-of-thought.

## Architectural Decision

```text
runtime boundary -> append RunEvent -> update checkpoint
saved run + reference case -> deterministic graders -> optional model graders
evaluation run -> per-case results + aggregate quality, cost, and latency
```

Trace writing is part of the application boundary. A successful event must not claim an artifact
or effect that was not committed.

## User-Visible Behavior

Completed runs print trace and metric summaries. New CLI modes list evaluation suites, run one
suite, and compare two saved configurations. Output separates deterministic failures from model-
grader judgments.

## Runtime Flow

1. Create root run event and propagate run, Worker, session, and logical-step IDs.
2. Emit start and terminal events for model, tool, context, checkpoint, citation, and report stages.
3. Reference large artifacts by hash and path rather than copying them into events.
4. Finalize derived metrics only from committed events.
5. Load versioned evaluation cases and execute isolated runs.
6. Apply deterministic graders first and optional structured model graders second.
7. Store per-case and aggregate results with exact configuration identity.

## Trace Data Contract

`RunEvent` contains schema version, event ID, parent event ID, run ID, optional Worker/session IDs,
event type, timestamps, status, provider/model, token usage, latency, budget snapshot, retry count,
and artifact references. Prompts, evidence text, user secrets, API keys, raw private reasoning, and
opaque encrypted reasoning content are excluded by default.

## Evaluation Contract

Required metrics are brief adherence, evidence-target coverage, citation completeness, citation
pointer validity, unsupported-claim count, source access strength, summary retention, repeated
failed actions, duplicate external execution, crash recovery, tool efficiency, model/tool calls,
token usage, estimated cost, and wall-clock latency. Deterministic provenance and recovery graders
are authoritative. Model graders use strict schemas and report model identity and rubric version.

## Persistence and Artifact Contract

```text
runs/<run-id>/trace.jsonl
evals/cases/*.jsonl
evals/results/<eval-run-id>/results.jsonl
evals/results/<eval-run-id>/summary.json
```

Generated traces and results remain ignored by Git. Versioned case definitions and grader code are
committed.

## Idempotency and Replay Contract

Event IDs derive from committed logical boundaries and cannot be appended twice. Resume reuses the
terminal event for completed steps. Regrading a saved immutable run is side-effect free and records
a new grader result version.

## Security and Privacy Boundary

Trace payloads use allowlisted fields and artifact hashes. Redaction is structural, not regex-only.
Run deletion removes trace and generated artifacts according to one documented retention policy.

## CLI Contract

```text
uv run deep_research.py --trace-inspect <run-id>
uv run evals.py --suite core
uv run evals.py --compare <result-a> <result-b>
```

## Observability Contract

The trace itself is the contract. Terminal summaries expose success rate, deterministic gate
failures, coverage, citation metrics, cost, latency, and artifact paths.

## Failure and Stopping Behavior

A required trace write failure stops mutation before the associated step is declared committed.
One evaluation case failure is recorded and does not abort the suite unless harness integrity is
compromised. Missing secrets skip real-provider cases explicitly rather than reporting success.

## Implementation Constraints

Start with JSONL and standard-library aggregation. Do not add hosted tracing, OpenTelemetry SDK,
dashboard, generic eval framework, or model-generated private reasoning traces.

## Manual Acceptance Scenario

Run one successful, one resumed, one citation-failed, and one context-limited case. Inspect causal
events and artifacts, run deterministic graders twice, compare summary-only and hybrid context
policies, and confirm identical saved runs receive identical deterministic results.

## Completion Criteria

Trace schema, causal integrity, redaction, resume deduplication, deterministic graders, optional
grader provenance, comparison output, and retained runtime regressions pass. The project has a
baseline result before v0.17 parallelism.

## Out of Scope

Hosted dashboards, distributed collectors, production alerting, online A/B routing, reward-model
training, SFT/RL data export, parallel Workers, and batch rollout generation.

## Known Limitations and Deferred Decisions

Local JSONL is not a high-volume telemetry backend. Model graders are fallible and cannot override
deterministic provenance failures. v0.17 uses this harness to justify parallelism.
