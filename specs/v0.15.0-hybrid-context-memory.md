# v0.15.0 — Hybrid Context Memory

## Status

Draft

## Learning Question

What improves when a resumed Worker receives immutable pinned state, one validated compressed
state, a bounded recent raw tail, and on-demand evidence retrieval instead of receiving only a
lossy summary?

## Problem and Rationale

Release 0.10.0 proves deterministic summary replacement, but summary-only continuation can lose
recent causal detail and cannot recover omitted evidence. Releases 0.11–0.14 provide durable
evidence, checkpoints, and replay-safe execution. Release 0.15.0 uses those foundations to compare
a hybrid context assembly policy with the v0.10 baseline.

Anthropic frames context engineering as repeatedly selecting the most useful tokens from a growing
universe of history, tools, and external data; it identifies compaction, external memory, and
subagents as complementary techniques. See
[Effective context engineering for AI agents](https://www.anthropic.com/engineering/effective-context-engineering-for-ai-agents).
OpenAI offers provider-managed compaction for long-running Responses workflows, demonstrating that
compaction is also a hosted production mechanism; see
[Responses compaction](https://openai.com/index/equip-responses-api-computer-environment/) and the
[`/responses/compact` reference](https://developers.openai.com/api/reference/java/resources/responses/methods/compact).
The [ReSum paper](https://arxiv.org/abs/2509.13313) supplies the periodic summary baseline used in
v0.10. This release retains application-visible state instead of adopting opaque provider items.

## Primary Mechanism

Assemble every resumed Worker input from four owned regions in a fixed order:

```text
pinned contract + validated summary + retrieved evidence + recent complete raw boundaries
```

Each region has an explicit budget and trust label. The policy is deterministic; the model cannot
delay compaction, reorder trusted and untrusted regions, or expand a region's budget.

## Architectural Decision

Pinned state contains instructions, approved brief, task, security notice, and remaining budgets.
Compressed state contains completed work, evidence references, unresolved questions, failed
directions, and next actions. Retrieval resolves evidence IDs from the ledger. Recent raw tail
retains the newest complete model/tool boundaries needed for local continuity.

## User-Visible Behavior

Every context boundary prints the projected size, region budgets, selected evidence IDs, number of
recent raw boundaries, summary version, and resulting session input projection. It never prints
private reasoning or full evidence content.

## Runtime Flow

1. Classify active items into complete response/tool boundaries.
2. Select the bounded most recent complete boundaries without splitting call/output pairs.
3. Generate and validate the summary from the replaceable older region.
4. Select evidence IDs from summary references and unresolved next actions.
5. Retrieve bounded excerpts from the persistent ledger.
6. Assemble regions in fixed order and enforce per-region and total budgets.
7. Persist the context manifest before the resumed model call.
8. Continue with all run-level budgets unchanged.

## Context Assembly and Budget Contract

Order is: system/developer instructions; approved brief; Worker task; trust notice; remaining
budgets; latest summary; retrieved evidence envelopes; recent complete boundaries; continuation
instruction. Brief, task, trust notice, IDs, and budgets are never truncated.

Initial learning defaults reserve at most 4,000 projected tokens for summary, 8,000 for retrieved
evidence, and 4,000 for recent raw tail, plus model/tool-schema/output allowance. Exact total limits
remain model-contract configuration. When over budget, remove low-relevance retrieved excerpts,
then discovery snippets, then oldest complete raw boundaries, then request a new summary. Never
split a function call from its linked output.

## State Ownership and Persistence Contract

Persist one `ContextManifest` per session containing region versions, evidence IDs, item IDs,
projections, and trimming decisions. Persist references, not duplicate evidence content. Pinned
state is application-generated; summary is model-generated and validated; evidence is untrusted
external content; raw tail consists of public provider response items and linked outputs.

## Persistence and Artifact Contract

Write each immutable context manifest under the run directory and reference the exact summary,
evidence, and recent-boundary artifact hashes used to assemble that session. Resume loads the
committed manifest; it does not recompute selection against a changed ledger.

## Idempotency and Replay Contract

Given identical pinned state, summary version, evidence ledger, raw-boundary IDs, and budget
configuration, context assembly is deterministic. Resume reuses the committed manifest rather than
rerunning selection.

## Security and Trust Boundary

Retrieved evidence is wrapped and labeled as untrusted. It cannot alter pinned instructions,
budgets, source identity, or tool permissions. Existing OWASP-derived least-privilege and prompt-
injection boundaries remain in force.

## CLI Contract

Default execution uses hybrid memory. A mechanism-focused acceptance flag may run the same saved
task with `summary_only` versus `hybrid` policy; it is not a general user-configurable memory DSL.

## Observability Contract

Expose region sizes, evidence IDs, raw-boundary count, trimming reasons, context policy version,
peak observed input, and summary count. Store manifests for later evaluation.

## Evaluation Contract

A fixed corpus marks must-retain task constraints, claims, evidence IDs, failed directions, and
unresolved questions before compaction. Tests measure retention, repeated failed actions, evidence
recovery, task drift, context size, model calls, tool calls, and completion against the v0.10
summary-only baseline. Readability or an LLM preference score alone is insufficient.

## Failure and Stopping Behavior

If pinned state plus mandatory schema allowance cannot fit, stop with `context_limit`. Invalid
summary or missing required evidence follows the v0.14 recovery contract. Failure to retrieve an
optional record removes it with a visible limitation; failure to retrieve evidence required by a
direct claim blocks successful completion.

## Implementation Constraints

Use the persistent ledger and checkpoint runtime. Do not add embeddings until deterministic ID and
text retrieval prove insufficient. Do not adopt provider-managed opaque compaction in this release.

## Manual Acceptance Scenario

Run a multi-session task containing one failed search direction, one selected-source finding, one
recent tool failure, and one unresolved comparison. Confirm all four survive hybrid continuation,
the selected source can be reloaded from evidence, complete recent boundaries remain paired, and
the saved comparison reports retention and cost against summary-only mode.

## Completion Criteria

Context assembly, manifest replay, trust labels, budget trimming, recovery, retention evaluation,
real-provider, and baseline comparison pass. Hybrid mode must show no regression in application-
owned provenance or budget invariants.

## Out of Scope

Learned context managers, vector similarity, agent-selected delete/rollback operations, cross-run
memory, provider opaque compaction, and parallel Workers.

## Known Limitations and Deferred Decisions

Fixed regional budgets remain heuristic and text retrieval may miss semantically related evidence.
Adaptive context orchestration remains experimental until the v0.16 evaluation harness can compare
it reproducibly.
