# v0.12.0 — Structured Claims and Citation Verification

## Status

Draft

## Learning Question

What becomes deterministically checkable when Worker findings are structured claims linked to
persisted evidence IDs and a separate citation stage must map report claims back to those records?

## Problem and Rationale

Release 0.11.0 preserves evidence, but Workers still return free-form notes and the report stages
copy URLs without a machine-checkable claim-to-evidence relation. Release 0.12.0 makes provenance
part of the result contract and introduces citation verification after drafting.

Anthropic reports that its production Research system passes gathered findings to a dedicated
CitationAgent that locates citations in source documents, and evaluates factual accuracy,
citation accuracy, completeness, source quality, and tool efficiency. See
[How we built our multi-agent research system](https://www.anthropic.com/engineering/multi-agent-research-system).
Anthropic's API citation feature further guarantees that returned citation pointers refer to
provided document text, illustrating why application-provided source content is stronger than
prompt-only URL generation; see the official
[citations documentation](https://platform.claude.com/docs/en/build-with-claude/citations).

## Primary Mechanism

Workers return a validated `WorkerResearchResult` containing bounded `ResearchClaim` values. Each
claim names zero or more evidence IDs and declares `direct`, `partial`, `conflicting`, or
`inference` support. After Write, a separate Citation stage produces structured mappings that the
application validates before Critic and Revise.

## Architectural Decision

```text
Evidence Ledger
    -> structured Worker claims
    -> combined claim ledger
    -> Markdown draft
    -> structured CitationDecision
    -> deterministic provenance validation
    -> Critic and Revise
    -> final Markdown report
```

The citation model proposes placement; the application validates identity, source access level,
and exact supporting excerpts. The model cannot introduce a URL or evidence ID absent from the
ledger.

## User-Visible Behavior

Every Worker result reports claim count, direct versus inferred count, and unmet evidence targets.
Before critique, the CLI prints citation-validation coverage. The final report uses ordinary URLs
near supported claims and explicitly labels material inference, conflict, and missing evidence.

## Runtime Flow

1. Require a structured Worker result rather than free-form terminal notes.
2. Validate every referenced evidence ID against the active run ledger.
3. Preserve claim IDs and evidence links while rendering combined notes for Supervisor and Write.
4. Generate the draft from the approved brief and validated claims.
5. Ask the Citation stage for claim, evidence, excerpt, and proposed location mappings.
6. Require every excerpt to be an exact substring of persisted bounded evidence.
7. Reject unknown IDs, fabricated URLs, mismatched excerpts, and overstated access levels.
8. Pass only validated mappings to Critic and Revise.
9. Validate that the final report does not introduce an unregistered citation URL.

## State Ownership and Data Contract

`ResearchClaim` contains claim ID, text, evidence IDs, support type, confidence band, limitations,
and evidence-target IDs. `WorkerResearchResult` contains task summary, claims, unresolved questions,
and unmet targets. `CitationDecision` contains claim ID, evidence ID, exact cited excerpt, and
proposed report anchor. All are strict Pydantic Structured Outputs with application semantic checks.

Direct claims require at least one evidence ID. Inference may cite inputs but must be labeled.
Conflicting claims retain all material conflicting evidence rather than selecting one silently.

## Persistence and Artifact Contract

Add `claims.jsonl`, `citation-map.json`, `draft.md`, `critique.md`, and `report.md` under the run
directory. Claims and mappings carry schema versions. Evidence remains canonical in
`evidence.jsonl`; citation artifacts reference rather than duplicate it.

## Idempotency and Replay Contract

Claim IDs are stable within one immutable Worker result. Re-running citation validation over the
same draft, claim ledger, and evidence ledger is deterministic. A regenerated draft creates a new
citation-map version rather than overwriting a mapping for different text.

## Security and Trust Boundary

Evidence and draft text remain untrusted model input. Citation validation never executes content
or follows embedded instructions. URLs are rendered only from application-owned ledger records.

## CLI Contract

Invocation remains unchanged. Citation-validation failure is visible and prevents a successful
final report; no flag disables provenance validation in this release.

## Observability Contract

Print claim counts, evidence-link counts, direct/inference/conflict counts, citation coverage,
unsupported claims, invalid mappings, and artifact paths without printing private reasoning.

## Evaluation Contract

Deterministic tests cover unknown IDs, missing direct evidence, exact-excerpt mismatch, fabricated
URLs, snippet-versus-selected-source strength, conflict preservation, final-report URL allowlisting,
and removal of evidence referenced by a claim. A small fixed corpus also measures citation
completeness and accuracy; model graders may supplement but not replace deterministic checks.

## Failure and Stopping Behavior

Invalid Worker structure is `model_error`. Missing evidence is a failed Worker result that later
failure-aware releases may recover. Invalid citation mapping stops before final revision. The
application never silently drops an unsupported material claim and still reports success.

## Implementation Constraints

Reuse Pydantic and the selected run-level model. Add no second provider, entailment model, browser,
vector store, or generic citation library. Preserve Markdown as the user-facing format.

## Manual Acceptance Scenario

Research a question with one direct finding, one qualified inference, and two disagreeing sources.
Confirm persisted structured claims, exact excerpt validation, rendered source URLs, explicit
conflict, rejection of an invented evidence ID, and final-report failure when a citation URL is
not present in the ledger.

## Completion Criteria

All structured, deterministic, real-provider, artifact, and regression scenarios pass. A reviewer
can traverse every material report citation to one persisted evidence record and originating tool
call.

## Out of Scope

Universal fact checking, truth adjudication between sources, automatic source-quality scoring,
cross-run claims, durable resume, parallel citation agents, and training a verifier.

## Known Limitations and Deferred Decisions

Valid provenance does not prove a claim true, and exact substring matching does not prove semantic
entailment. Recovery and retry are deferred to v0.13 and v0.14; broader evaluation is deferred to
v0.16.
