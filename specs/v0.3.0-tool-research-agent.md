# v0.3.0 — Tool-Using Research Agent

## Status

Verified

## Learning Question

How does a model use custom tools when the application implements the function-calling
loop, owns the response history, and enforces simple limits?

## Problem and Rationale

Release 0.2.0 has explicit Write, Critic, and Revise calls, but it cannot gather external
evidence. Release 0.3.0 adds one bounded research Agent before those stages. The Agent may
select Tavily web search or arXiv paper search, receive the result, and continue until it
returns research notes.

The release teaches only the core mechanism. `deep_research.py` contains the prompts,
Agent loop, Write-Critic-Revise workflow, CLI, and terminal output. `agent_tools.py`
contains the tool definitions and functions. The program does not write reports, traces,
or other application output artifacts.

The design follows the
[OpenAI function-calling guide](https://developers.openai.com/api/docs/guides/function-calling),
the [Tavily Python SDK documentation](https://docs.tavily.com/sdk/python/quick-start), and
the [arXiv API manual](https://info.arxiv.org/help/api/user-manual.html).

## User-Visible Behavior

The CLI accepts one question and runs four stages:

1. **Research** uses a bounded Agent loop and the two search tools.
2. **Write** drafts a report from the question and research notes.
3. **Critic** reviews the draft against the question and notes.
4. **Revise** produces the final Markdown report.

The terminal shows stage progress, Research model turns, selected tool names, tool success
or failure, remaining tool budget, and the final report. It does not print tool payloads,
response history, secrets, or model reasoning items.

## Runtime Flow

```text
question
→ load and validate configuration
→ initialize response history with the question
→ Research Agent loop
    → call the model with two custom function definitions
    → append model output items to history
    → if the model requested functions:
        → execute each one synchronously in response order
        → append each linked function_call_output
        → continue within the limits
    → otherwise return non-empty research notes
→ Write(question + research notes)
→ Critic(question + research notes + draft)
→ Revise(question + research notes + draft + critique)
→ print the final Markdown report
```

## Responses API Contract

`llm_call` is a thin wrapper around synchronous `client.responses.create`. Every request
uses the configured model and `store=False`. Research requests provide custom function
definitions without setting `parallel_tool_calls`. The model may return zero, one, or
multiple function calls in one response; the application handles every returned call
synchronously in response order.

The Agent starts with one user message. After each response, it appends every item from
`response.output` in order. For each function call it appends:

```json
{
  "type": "function_call_output",
  "call_id": "<provider call id>",
  "output": "<JSON-encoded tool result>"
}
```

The next request receives the complete history. A response without a function call must
contain non-empty `output_text`, which becomes the in-memory research notes. Write,
Critic, and Revise are explicit text requests that receive only the upstream content they
need.

## Tool Contract

`agent_tools.py` provides two strict function definitions:

- `tavily_search_tool(query, max_results)` returns web result titles, snippets, and URLs.
- `arxiv_search_tool(query, max_results)` returns paper titles, authors, dates, abstract
  URLs, summaries, and PDF URLs.

`query` must be a non-empty string. `max_results` must be an integer from 1 through 5.
Malformed arguments, unknown tools, and external failures become a short error result so
the Agent can adapt. The tools do not fetch selected pages, validate citations, score
sources, or retry failed calls.

## CLI Contract

```text
uv run deep_research.py \
  "What do recent papers and current web sources say about tool-using agents?"
```

The question and these environment variables are required:

- `OPENAI_API_KEY`;
- `MODEL_NAME`;
- `TAVILY_API_KEY`.

`python-dotenv` loads the repository-root `.env`. Normal output goes to standard output
and fatal errors go to standard error. Missing input or configuration makes no external
request.

## Limits and Stopping Contract

Research allows at most 10 model turns, 8 tool execution attempts, and 5 results per call.
arXiv requests have a 30-second timeout.

Malformed, unknown, and failed calls count toward the tool budget. If one response contains
more calls than the remaining budget, calls within the budget are attempted and later calls
receive a linked `Tool call limit reached.` error without external execution. After the
eighth attempt, the next Research request omits tool definitions and asks the model to
synthesize from its history. The loop succeeds on non-empty text without a function call.
It fails on an API exception, empty required output, or failure to finish within 10 turns.

## Observability Contract

Live terminal output is the complete observability mechanism for this release. It shows
the four stages, Research turns, tool activity, budget exhaustion, failures, and the final
report. Structured tracing is not included.

## Artifact Contract

Release 0.3.0 creates no run directory and writes no application output files. Research
notes, draft, critique, and final report remain in memory; only the final report is printed
in full.

## Failure Behavior

Missing input or configuration, fatal Responses API errors, empty required output, or an
exhausted iteration limit print an error and exit nonzero. Tool errors are returned to the
Agent as linked function outputs and do not by themselves stop the workflow.

## Implementation Constraints

- Keep prompts, the Agent loop, Write-Critic-Revise, CLI, and terminal output in
  `deep_research.py`.
- Keep tool definitions and functions in `agent_tools.py`.
- Prefer short functions, plain lists and dictionaries, and direct control flow.
- Express multi-line prompts with triple-quoted f-strings.
- Use the synchronous OpenAI Responses API directly.
- Do not set `parallel_tool_calls=False`; handle every function call returned in a response
  synchronously in response order.
- Do not write application output files or create run directories.
- Do not add tracing, planning, Pydantic models, retries, concurrency, hosted tools, MCP,
  automated tests, Ruff, or mypy.

## Manual Acceptance Scenario

With valid configuration, run:

```text
uv run deep_research.py \
  "What evidence do recent arXiv papers and current web sources give for using tools in \
  LLM agents? Cite sources and distinguish papers from web guidance."
```

Confirm that:

1. Research, Write, Critic, and Revise complete in order;
2. Research uses both Tavily and arXiv without printing their payloads;
3. the final report is non-empty and cites returned sources;
4. the program creates no run directory or application output files; and
5. the process exits successfully.

Then run without `TAVILY_API_KEY` and confirm a configuration error, no external request,
and a nonzero exit. In an isolated runtime check, reduce the tool limit to one and confirm
the next Research turn receives no tools. In another isolated check, return two function
calls in one response and confirm both linked outputs are in history before the next model
turn.

## Completion Criteria

The specification may become `Verified` after Python compilation, the success scenario,
the configuration-failure scenario, and the bounded-stop scenario pass; terminal output
and the final report are inspected; and the project documentation, dependencies, lock
file, and version match the implementation. Ruff and mypy are not required.

## Out of Scope

File artifacts, structured traces, selected-page reading, arbitrary URL fetching,
deterministic citation validation, source-quality scoring, query planning, structured
research plans, Pydantic models, clarification, approval points, retries, caching,
streaming, context compaction, checkpoints, concurrent tool execution, multi-agent
execution, hosted OpenAI tools, MCP, automated evaluation, automated tests, Ruff, and mypy.
