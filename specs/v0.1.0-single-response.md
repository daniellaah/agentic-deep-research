# v0.1.0 — One Responses API Call

## Status

Released

## Learning Question

How do we talk to OpenAI LLM through Responses API?

## Problem and Rationale

This release establishes the smallest runnable baseline: one question, one synchronous
Responses API call, and one Markdown report. It is not an Agent because it has no loop,
tools, history, or stopping decisions.

The release uses the Responses API because the official API exposes one response boundary,
top-level `instructions`, text `input`, the `store` control, and aggregated `output_text` through
the SDK. Those fields are sufficient for the smallest observable baseline without introducing a
conversation or Agent abstraction. See the official
[Responses API reference](https://developers.openai.com/api/reference/cli/resources/responses/methods/create).

## User-Visible Behavior

The CLI loads configuration, accepts one question, prints concise progress and the answer,
then writes the answer to `runs/<run-id>/report.md`.

## Runtime Flow

```text
question
→ load and validate configuration
→ llm_call(...)
→ read response.output_text
→ print and save the answer
→ exit
```

## Responses API Contract

`main` invokes `llm_call` exactly once. `llm_call` uses the synchronous `OpenAI` client and
returns the original SDK `Response`.

The request contains:

- `model=MODEL_NAME`;
- research-assistant `instructions`;
- `input=question`; and
- `store=False`.

The response must contain non-empty `output_text`.

## CLI Contract

```text
uv run deep_research.py \
  "Explain in three concise bullets how a trace helps debug an AI agent."
```

The question is required. `python-dotenv` loads the repository-root `.env`, while existing
process environment variables take precedence. `OPENAI_API_KEY` and `MODEL_NAME` are
required. Normal output goes to standard output; fatal errors go to standard error.

## Trace Contract

This release does not create a structured trace or `trace.jsonl`. Tracing begins when a
later release introduces a multi-step Agent loop.

## Artifact Contract

A successful run creates:

```text
runs/<run-id>/
└── report.md
```

`report.md` contains `response.output_text`. The run directory is rooted at the repository,
independent of the caller's current working directory. Configuration and API failures
create no run directory; an artifact-write failure may leave an incomplete directory.

## Failure and Stopping Behavior

The command fails for missing input or configuration, an API error, empty `output_text`, or
an artifact-write error. It makes at most one model call and performs no retries.

## Implementation Constraints

- Keep all runtime behavior in `deep_research.py`.
- Use the synchronous OpenAI Responses API directly.
- Keep `llm_call` as a thin wrapper that returns the SDK `Response`.
- Use direct functions and standard-library utilities, plus `python-dotenv`.
- Do not add tools, loops, history, trace events, concurrency, asynchronous code, provider
  abstractions, or automated tests.

## Manual Acceptance Scenario

Provide valid `OPENAI_API_KEY` and `MODEL_NAME`, then run:

```text
uv run deep_research.py \
  "Explain in three concise bullets how a trace helps debug an AI agent."
```

Confirm that:

1. one model request is made and the answer appears in the terminal;
2. `report.md` contains the answer;
3. the new run directory does not contain `trace.jsonl`; and
4. the process exits successfully.

Then run without `MODEL_NAME` and confirm that the command reports a concise error, makes
no API request, creates no run directory, and exits unsuccessfully.

## Completion Criteria

The specification may become `Verified` after both manual scenarios pass, Ruff and mypy
pass, exactly one Responses API call is confirmed, the report is inspected, and the README,
tech stack, and roadmap match the implementation. Only then may the project create the
`v0.1.0` tag.

## Out of Scope

Tools, Agent loops, conversation history, structured tracing, search, citations, planning,
streaming, retries, checkpoints, critique, concurrency, multi-agent execution, and
automated evaluation.
